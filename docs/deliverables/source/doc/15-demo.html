Chapter 15Demonstration procedure

This chapter describes a step-by-step procedure for demonstrating AegisEO in about 12 minutes: what to run, what each step shows, and how the system behaves if something goes wrong. Every step uses features described in Chapters 4 to 8.

15.1 Preparation

The day before:

  1. Start the two programs (Appendix A gives the full installation commands): 
    # terminal 1
cd backend
.venv\Scripts\activate
uvicorn aegis.main:app --port 8000
# terminal 2
cd frontend
npm run dev                # then open http://localhost:5173
  2. Run every real check you plan to show once, in advance. A first check of an area takes about 3 to 10 minutes, mostly downloading images. The downloaded image windows are saved, so a repeat of the same check takes seconds (3 to 56 s in the measured runs). This turns a waiting period into a live demonstration.
  3. Run one practice run as well. It needs no internet and finishes in under a minute.
  4. Open About → Where the data comes from and press Check them all again, so you know in advance if a public service is down.

Thirty minutes before: start both programs; set the browser zoom to 100% and turn off notifications; open the finished Sindh check and practice run in separate tabs as a backup; keep the slides at hand in case the computer or network fails.

Keep secrets off the screenThe demonstration needs no keys or passwords: the optional Claude, FIRMS and webhook settings are not used. Do not open the .env file or a terminal that prints settings while the screen is shared.

15.3 If something goes wrong

ProblemWhat to do
The internet is slow or down.Show the checks that are already finished: they are stored on the computer. The background map needs the internet; without it, the map waits up to 8 seconds and then draws a plain grey background, while AegisEO's own layers (detected area, squares, places, before/after images) still appear because they come from the local server. A practice run works completely offline.
A new real check is needed without internet.Start the backend in offline mode (AEGIS_OFFLINE=true). An area that was already checked then runs from the saved data (tested for Sindh on 8 November 2026: the same result in 8 seconds). A new area cannot work offline, and AegisEO says so instead of inventing data.
A check takes too long.Leave the page (the check keeps running on the server) and continue with a finished check. Press Stop if needed; the check ends as "Stopped".
A public service fails during the demonstration (for example OpenStreetMap).Use it as a demonstration: the result says which information is missing and lowers its confidence instead of failing. Benchmark scenarios A04 and A05 test exactly this.
The server stops.Start it again. Checks that were running are marked "Interrupted" and can be started again with the Run again button; finished checks and decisions are kept.
The computer fails.Present from the slides, which contain genuine screenshots of every step above.
