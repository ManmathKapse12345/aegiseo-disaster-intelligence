Chapter 10Project structure: folders and files

The repository (the project's folder under version control with Git, a system that records every change to the files) contains about 200 tracked files. This chapter is a map of where things are.

10.1 Top level

Folder / fileContents
backend/The Python server: the aegis package, tests, scripts, dependency lists, Dockerfile.
frontend/The web interface: src (TypeScript/React), public (icons and images), e2e (browser tests), build configuration, nginx configuration, Dockerfile.
models/The trained neural networks (five *.pt files of 1.8-4.8 MB), their training records (*.json), evaluation.json, selection.json (which model is deployed) and the training log.
docs/Technical documents (architecture, agent design, data, model card, evaluation, benchmark, acceptance runs, failure analysis, API, UI design, final report), figures, and deliverables/ (this report, the slides, screenshots and their sources).
deploy/Hugging Face, Oracle Cloud and Cloudflare-tunnel deployment files.
docker-compose.ymlThe three-container deployment (PostGIS, API, web).
.env.exampleEvery setting (environment variable) with comments; copy to .env to use.
data/ (not in Git)Created at run time: the SQLite database, artefacts, image cache, downloaded training data, logs.

10.2 The backend package backend/aegis

ModuleResponsibility
main.pyCreates the FastAPI application: middleware, error handlers, routers, serving the built interface.
config.pyAll settings with defaults (read from AEGIS_* environment variables): storage, security, limits, sources, optional keys.
api/routes_analyses.py, routes_review.py, routes_system.py (endpoints); schemas.py (request validation); deps.py (identity, roles, rate limiter).
jobs.pyJob manager (thread pool), restart recovery, default search ranges, building the agent's configuration.
agents/Orchestrator, specialists, state, tools and toolbox, guardrails, memory, narrative, recorder (Section 9.5).
analysis/hazards.py (flood, wildfire, landslide detection), impact.py (exposure), prioritize.py (squares and scores), indices.py, sar.py (Lee filter, log-ratio), terrain.py (slope, height above drainage), bundle.py (the set of loaded layers).
ml/models.py (U-Net and gated fusion), features.py (model inputs), inference.py (calibrated prediction with MC dropout, radar-specialist hybrid), train.py, evaluate.py, metrics.py, baselines.py (Otsu, MNDWI), augment.py, data.py, prepare.py.
sources/stac.py (catalogue search, signing, grouping), imagery.py (reading Sentinel-1/2 onto the grid), osm.py, population.py, feeds.py (GDACS, USGS, FIRMS, Open-Meteo), places.py (Nominatim), registry.py (source list and health).
geo/aoi.py (area validation and size limit), grid.py (common grid, pixel budget), raster.py (warping and caching), vector.py (polygons).
net/http.pyThe resilient HTTP client.
reports/layers.py (map overlays, GeoTIFF), documents.py (PDF, CSV, GeoJSON).
actions.pyHuman decisions: approving/rejecting warnings, review decisions, priority changes, re-runs, deletion.
db.pyDatabase models (13 tables), PostGIS columns, sessions, audit helper.
scenarios.py, synthetic.pyCase studies; the practice-scene generator.
benchmark.pyThe agent benchmark (12 scenarios and 8 safety probes).
knowledge/Six method documents used for cited guidance.
observability.py, logging_config.pyPrometheus metrics and JSON logging.

Other backend folders: tests/ (10 test files, 93 tests) and scripts/ (downloading Sen1Floods11, training all models, writing the acceptance report, rendering the explainer images and practice previews).
