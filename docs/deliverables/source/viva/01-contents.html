How to use this document

The questions are grouped by topic and become harder from Part 1 to Part 11. Each question is marked with its level:

  • Basic what the project is and does; expected from anyone presenting it.
  • Intermediate how a part works, with numbers and file names.
  • Challenging critical questions about assumptions, weaknesses and alternatives.

Each answer is written to be spoken in about 30 to 60 seconds. A grey box below an answer contains a likely follow-up question and its answer. Technical terms are explained the first time they appear in this document. References such as "(Doc 7.5)" point to the chapter and section of the project documentation where the topic is explained in full.

A reliable way to answer
  1. Answer the question in one sentence first.
  2. Then give the evidence: a number, a file, or what the screen shows.
  3. Then, where it fits, name a limitation. Examiners trust a candidate who knows where the system stops working.
  4. If you do not know, say so and explain how you would find out (for example "the threshold is in guardrails.py; I would check it there").
Keep facts and plans apartAlways distinguish what AegisEO does today from what it could do in future (Doc Chapter 16). Never describe a proposal as a feature, and never describe practice (simulated) data as real.
